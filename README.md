# OBD Meter (E90 向けメーターダッシュボード)

OBD Fusion のダッシュボード機能に相当する Android アプリの土台です。
USB 接続の OBD アダプターから車両データを読み、アナログ / バー / デジタルのメーターで表示します。

## できること (v0.1)

- **接続方式を設定で切替**: シミュレーター / USB
- **USB アダプターを設定で切替**
  - OBDLink SX / EX (ELM327 互換、汎用 OBD2) … 推奨
  - K+DCAN ケーブル (INPA 互換、BMW-FAST で DME に直接問い合わせ) … 実験的
- **カスタマイズできるダッシュボード**
  - 複数ページ (左右スワイプで切替)、ページごとに 1〜4 列
  - メーターの追加・削除・並べ替え、表示スタイル (アナログ / バー / デジタル) の変更
  - 設定は端末に保存
- **表示項目 (25 種)**: 回転数、車速、水温、吸気温、油温、負荷、スロットル、アクセル、MAP、大気圧、MAF、点火時期、燃調 (B1/B2 短期・長期)、燃料残量、触媒温度、外気温、ECU 電圧、経過時間、バッテリー電圧、ブースト圧・燃料消費量・瞬間燃費 (計算値)
- 車両が対応していない項目は自動で「非対応」表示にして読み出しをスキップ
- 表示中のページの項目だけを読むので、ページを分けるほど更新が速くなる
- 変化の遅い項目 (温度・電圧など) は間引いて読み、回転数などの更新を優先
- **通信ログ画面**: 送受信の生データを表示・共有できる (実車でうまくいかないときの調査用)
- 自動再接続、接続中の画面消灯防止

## ビルド方法

1. Android Studio (Ladybug 以降推奨) で、このフォルダ (`OBDMeter`) を **Open** する
2. Gradle Sync が終わるのを待つ (初回は依存ライブラリをダウンロード)
3. Android 端末を USB デバッグで接続し、▶ Run

### GitHub Actions でビルド

`.github/workflows/android.yml` を同梱しています。GitHub にリポジトリを作って push すると自動でビルドされます。

1. GitHub で空のリポジトリを作成
2. このフォルダで以下を実行
   ```
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```
3. リポジトリの **Actions** タブ → 最新の実行 → 下部の **Artifacts** から `OBDMeter-debug-apk` をダウンロード (zip の中に APK)
4. `git tag v0.1.0 && git push origin v0.1.0` のようにタグを push すると、**Releases** にも APK が添付されます
   (スマホのブラウザから直接ダウンロードできて便利です)

Actions タブの「Run workflow」から手動実行もできます。単体テストが失敗した場合はテストレポートが Artifacts に残ります。

インストール時は端末側で「提供元不明のアプリ」の許可が必要です。

### コマンドライン

コマンドラインの場合は `./gradlew assembleDebug` で `app/build/outputs/apk/debug/app-debug.apk` ができます。
単体テストは `./gradlew test` です (通信プロトコルの解析処理を疑似アダプターで検証)。

- minSdk 26 (Android 8.0) / targetSdk 35
- Kotlin + Jetpack Compose、USB 通信は [usb-serial-for-android](https://github.com/mik3y/usb-serial-for-android)

## 動作確認の手順 (おすすめ順)

### 1. シミュレーターで画面確認 (車不要)
設定 → 接続方式「シミュレーター」→ 戻って「接続」。
加速・巡航・減速を繰り返す疑似データでメーターが動きます。ページ編集もここで試せます。

### 2. OBDLink SX/EX で実車 (本命)
1. 端末に USB OTG アダプター経由で OBDLink を接続し、OBD ポートに挿す
2. イグニッション ON (エンジン始動でも可)
3. 設定 → 接続方式「USB」、USB アダプター「OBDLink SX / EX」
4. 「接続」→ USB 使用許可ダイアログで許可
5. 通信プロトコルの初期値は **ATSP6 (CAN 11bit 500k)**。2008/11 製の E90 (D-CAN 車) に合わせています。
   つながらない場合は「自動判別 (ATSP0)」も試してください。

### 3. K+DCAN ケーブル (実験的)
1. ケーブルのスイッチを車両に合わせる (2007/03 以降 = D-CAN 側)
2. 設定 → USB アダプター「K+DCAN ケーブル」、ECU アドレスは `12` (DME)
3. 「接続」

このケーブルは BMW 独自の通信路を使うため、汎用 OBD の問い合わせ先 (CAN ID 0x7DF) には届きません。
DME に直接 Mode 01 を送っており、**DME がこれに応答するかは実車で要確認**です。
応答がなければ、通信ログ画面の内容を共有してください。BMW 独自の値の読み方に切り替えて対応します。

## メーターの編集 (v0.2)

- ダッシュボード右上の **鉛筆ボタン** でレイアウト編集モードになります
  - **ドラッグ**: 移動 / **右下の ◢ をドラッグ**: サイズ変更 (24 × 12 マスに吸着)
  - **タップ**: メーターの設定 (表示項目・表示形式・表示名・範囲・小数桁・警告値・色・最前面へ・削除)
  - 下のバー: メーター追加 / 1〜4 列で並べ直す / ページ管理
- 項目選択の一覧には **標準の項目** と **カスタム PID** の両方が出ます

## カスタム PID

設定 → カスタム PID (またはメーター追加の一覧の「カスタム PID を作成」) から登録します。

| 項目 | 内容 |
| --- | --- |
| モード / PID | 16 進。例: Mode `22` / PID `4205` |
| ヘッダー | OBDLink: ATSH の値 (例 `7E0`)。K+DCAN: 送信先 ECU (例 `12` = DME)。空欄で既定 |
| CAN 拡張アドレス | OBDLink の ATCEA。BMW の 6F1 系で使う場合のみ |
| 式 | 応答データ (サービス ID と PID のエコーを除く) の 1 バイト目が `A`、2 バイト目が `B` … |

式の例: `(A*256+B)/4` 、 `A-40` 、 `signed(A)*0.5` 、 `signed16(A*256+B)/10` 、 `bit(A,3)`
使える関数: `abs min max round floor signed signed16 bit`

編集画面では、サンプルのバイト列で式を試したり、接続中の車両から 1 回だけ読んで生データと計算結果を確認できます。

## うまく動かないとき

右上のリスト アイコン → 通信ログ → 共有ボタンでテキストを送れます。
TX が送信、RX が受信、赤字がエラーです。よくあるパターン:

| ログの内容 | 原因と対処 |
| --- | --- |
| 「USB アダプターが見つかりません」 | OTG ケーブル、端末の OTG 対応を確認 |
| ELM で `UNABLE TO CONNECT` | イグニッション OFF、またはプロトコル不一致 → ATSP を固定 |
| ELM で応答が文字化け | ボーレート違い → 設定で 115200 / 38400 などを試す |
| DCAN で「エコーが返りません」 | ケーブル未接続、ドライバー不一致 |
| DCAN で `7F 01 11` / `7F 01 12` | DME が Mode 01 非対応 → BMW 独自方式への切替が必要 |

## 構成

```
app/src/main/java/com/obdmeter/
├─ core/       通信プロトコルと PID 定義 (Android 非依存・単体テスト済み)
│  ├─ Transport.kt          物理層の抽象 (USB / 将来の Wi-Fi)
│  ├─ Elm327Protocol.kt     OBDLink / ELM327 (AT コマンド)
│  ├─ BmwFastProtocol.kt    K+DCAN ケーブル (BMW-FAST テレグラム)
│  ├─ SimulatorProtocol.kt  疑似車両
│  └─ Pids.kt               表示項目の定義・換算式・読み出しスケジューラ
├─ usb/        USB シリアル通信、使用許可
├─ session/    接続管理・ポーリング・通信ログ
├─ data/       設定とダッシュボード構成の保存
└─ ui/         画面 (ダッシュボード、編集、設定、ログ) とメーター描画
```

新しい接続方式は `Transport` と `ObdProtocol` を実装すれば追加できます。
